## 3. 目标与验收

### G1（P0）对照证据：证明“不是普通 RAG”

做一次可复核的对照实验，同一个目标、同一套语料、同一个模型：

- A 组：单 Agent 直接检索 + 生成，不做任务拆分、不做引用门禁、不做验收。
- B 组：证据工作台当前流程。

首轮结果（2026-10-26）已经证明：**A 并不弱**。A 的 11 条结论全部能人工定位（文件 + 章节 + 引语），
B 的 14 条 claim 中 13 条可人工定位、14 条可机器验证。因此 G1 不再声称“工作台引用更准”，改为证明**可交付性差异**：

| 指标 | 定义 |
|---|---|
| 结论条数 | 两组各自输出的事实性结论数 |
| 可人工定位 | 文件 + 章节 + 原文片段能在语料中核对 |
| 机器可验证 | 每条 claim 带 evidence id + `chars` locator，脚本可解析回块 |
| 可拒绝 | 把 evidence id 换成未检索到的 id，门禁必须拒绝 |
| 完成签名 | 是否有 `team.completed` + 退出码 + 结构化验收 |
| 冲突呈现 | 是否把跨来源差异并列（本语料暂无真实冲突对，标 N/A） |

验收标准：

- 原始输出、参数、评分表全部落盘到 `docs/evaluation/`，可复跑；
- B：机器可验证率 100%，且负向测试（伪造 evidence id）被拒绝；
- A：机器可验证率 0%（无 evidence id），人工定位率如实记录，不要求它失败；
- PPT 增加 1 页，标题只写“同一答案质量，两种可交付性”，不写“我们引用更准”。

不追求“统计显著”，只做一个诚实、可回查的案例。

## 8. 实现前已定死的口径（builder check 后补充）

### 8.1 “结论”与“可定位引用”怎么算

- 评分对象是 `results.json` 里的结构化 claim（`text` + `type` + `evidence_ids`），不是整段散文。
- 由独立脚本把每个 `evidence_ids` 解析回语料块，核对三件事：文件、`chars:start-end`、原文片段确实包含引用的句子；**不拿 `app/citations.py` 的门禁结果当分数**，否则是自证。
- 基线 A 必须输出同一 claim schema；两边用同一个独立解析器打分。
- 这样 B 的分数不依赖自己的门禁，A 也不会因为“没有结构化输出”被直接判负。

### 8.2 基线 A 到底做什么

- 与 B 使用同一个 FTS5 索引、同一个模型、同一题；证据预算取 B 两个任务实际证据预算之和（一次性给 A 更多上下文，避免“算力不公平”的质疑）。
- A 只做一次检索 + 一次生成，不拆任务、不做引用门禁、不做结构化验收；允许它自由写散文，评分时再抽取 claim。
- 明确在 PPT 写清：B 多调用是方法本身（规划/取证/成稿），不是靠更多算力堆出来的；A 的上下文预算不少于 B。
- 这是案例对照，不宣称统计显著。

### 8.3 第三工作区的具体范围

- 名称：`medical-ai-compliance`；描述：医疗健康数据与 AI 辅助诊疗合规。
- 只做配置：`app/workspaces.py` 注册、`app/goal_guard.py` 域词表、`corpus/medical-ai-compliance/` 预置文本、seeding；不改引擎逻辑。
- 目标文档（只收可核对纯文本，来源为 gov.cn / nhc.gov.cn / npc.gov.cn 等）：
  1. 基本医疗卫生与健康促进法
  2. 医师法
  3. 人类遗传资源管理条例
  4. 涉及人的生命科学和医学研究伦理审查办法
  5. 医疗卫生机构网络安全管理办法
  6. 国家健康医疗大数据标准、安全和服务管理办法（试行）
  7. 人工智能医用软件产品分类界定指导原则
