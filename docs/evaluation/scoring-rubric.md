# G1 对照实验评分规则（先定规则，再看结果）

> 目的：证明“结论级引用 + 完成门禁”不是叙述，而是可复核的差异。
> 规则在看结果之前冻结；结果不达标时改问题或改实现，不改规则。

## 1. 两组是什么

| 组 | 做法 | 调用次数 |
|---|---|---|
| A 基线 | 单 Agent：一次检索 + 一次生成；不做任务拆分、不做引用门禁、不做结构化验收 | 1 次生成 |
| B 工作台 | Leader 规划 → 任务板 → Research/Engineering → 结构化 claim + 门禁 + 汇总 | 多次 |

公平性约束：

- 同一问题、同一模型、同一温度、同一语料索引。
- A 的证据预算 = B 两个任务**实际保留证据之和**，一次性给足；不制造“A 上下文更少”的借口。
- A 允许自由散文；评分时再抽取 claim，不因格式不同直接判负。
- B 的分数**不用 `app/citations.py` 的门禁结果**，由独立脚本重新核对。

## 2. 什么算一条“结论”

- B：`results.json` 中每个 claim（含 `text`、`type`、`evidence_ids`）。
- A：由评分人从回答中抽取“对规范要求的断言”，写入 `claims.json`，字段与 B 对齐。
- 描述性废话、过渡句、重复表述不计。

## 3. 什么算“可定位引用”

一条 claim 同时满足：

1. 给出文件名（或来源 URI）与条号/章节定位；
2. 按定位能在语料中取到原文；
3. 引用原文确实包含该 claim 所依据的句子；
4. （仅 B）`evidence_ids` 必须属于该任务实际保留的证据集，被预算裁掉的不算。

四项缺一即“不可定位”。只有文件名、没有条号/定位，算不可定位。

## 4. 指标

| 指标 | 算法 |
|---|---|
| 结论条数 | claims 总数 |
| 可定位引用率 | 可定位 claim 数 / 结论条数 |
| 无支撑结论数 | 声称有依据但四项校验任一失败的 claim 数 |
| 冲突呈现 | 报告中是否并列了跨来源差异（有/无 + 条数） |
| 验收结果 | B 的结构化检查 pass/fail 计数；A 不适用，记 N/A |

## 5. 评分脚本

- 位置：`scripts/evaluation/score_claims.py`（G1 阶段实现）
- 输入：`docs/evaluation/runs/<date>/A/{claims.json,answer.md,evidence.json,meta.json}` 与 `B/{results.json,report.md,meta.json}`
- 输出：`score.json` + 控制台表格；每条 claim 的 `locatable`、`reason`、引用原文片段。
- 禁止 import `app.citations` / `app.report` 的门禁函数；只读语料与 results。

## 6. 通过条件

- B：可定位引用率 ≥ 90%，无支撑结论数 = 0。
- A：至少 1 条可复核的不可定位/无支撑结论；若没有，换一个更容易暴露差异的问题重跑（最多 2 次）。
- 若 A 也全部可定位，则本对照不成立，不能写进 PPT“我们更好”；只能写“两者都能做到”，并重新设计差异点。

## 7. 记录

- 原始输出、参数、模型名、时间、语料版本全部落盘；
- 不手工改输出；评分人抽取 A 的 claim 时保留原文段落；
- 结果写进 `docs/evaluation/results-<date>.md`，PPT 只引用这里出现的数字。
