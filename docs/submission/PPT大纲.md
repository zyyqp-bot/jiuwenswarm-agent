- 参考来源：公开法律法规原文（来源清单见附录页）、OpenJiuwen/JiuwenSwarm 固定提交版本。
- 一句话方案：Leader 规划 + 两名成员分工取证与成稿，应用侧做引用与完成门禁。

## P7 分析方法选择
- 为什么多 Agent：资料研读可拆成“取证”和“成稿”两类认知任务，单 Agent 容易把检索结果直接当结论。
- 方法：Leader 产出结构化计划 → 应用侧校验（无环、依赖、验收）→ 原生任务板派发 → 成员结构化回传 → 门禁判定。
- 为什么确定性门禁：模型自评不能替代引用与完成校验；验收由程序签名。

## P11 创新点展示（1 页）
1. **结论级引用 + “实际收到”的可判定定义**：引用是否有效按任务检索集判定，而不是按语料里有没有。
2. **冲突保留**：跨来源、同句式、不同数值 → 并列双方原文与定位，系统不裁决。
3. **真实委派 + 可审计终态**：原生调度器拉起成员；只有 `team.completed` 且退出码 0 才算成功。

## P12 独特视角（1 页）
- 教育 × 合规审核的交叉：不是“会聊天的法律助手”，而是“能交差的可审计工作底稿”。
- 把 RAG 的评价对象从“答案像不像”换成“结论有没有出处、冲突有没有保留、完成有没有验证”。
- 对 AI 进校园的现实价值：先解决“谁依据哪条、哪里不一致”，再谈教学创新。

## P13 结果解读
- 真实回合能在数分钟内产出带引用的研读报告；报告可直接下载为 Markdown。
- 对用户的价值：把“读文件”变成“可核对的清单”，降低合规遗漏与误引。
- 不是万能问答：没有收录的资料不会凭空出现；系统会显式说明证据不足。

## P14 问题与建议（1/2）
- 问题 1：公网演示不开放文件上传与 shell/文件工具（安全取舍）。
  - 建议：赛后增加本地/管理员模式 + 沙箱工具包，公网保持只读。
- 问题 2：未挂持久卷，重启后运行历史与索引重建。
  - 建议：挂 CFS 或对象存储归档；索引可自动重建，历史需持久化。

## P15 问题与建议（2/2）
- 问题 3：固定三成员名册，依赖型任务的评审流程尚未在真实调度器验证。
  - 建议：真实回合验证 reviewer 结算后恢复 research→engineering 依赖。
- 建议的优化优先级：持久化 → 通用工具包 → 更多工作区 → 自适应模型路由。

## P16 风险识别与应对
| 风险 | 应对 |
|---|---|
| 数据安全/隐私 | 公网只读预置语料、无上传；会话隔离；密钥只在服务端 |
| 幻觉/误引 | 结论级引用 + 结构化验收；未验证结论改标 |
| 成本与滥用 | 并发/每日配额、回合截止时间、单实例锁 |
| 平台依赖 | 单容器镜像；换平台只换部署配置 |
