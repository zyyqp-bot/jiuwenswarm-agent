## 1. 一句话定位

一个由 Leader 规划、两名专业成员分工执行的多 Agent 工作台：用户给出目标，Agent 自己拆任务、检索授权资料、逐条引用原文，交付一份**每条结论都能回查、冲突不被消解、未知项显式列出**的成果。

首个场景选在教育与合规研读：教师、校方或合规人员面对不断更新的公开政策文件，需要的是“有出处的结论”，而不是一段无法追溯的生成文本。

## 2. 要解决的问题

大模型做资料研读有三个反复出现的问题：

1. **引用到“答案”而不是“结论”**：整段回答末尾挂一个链接，读者无法判断哪句话由哪条原文支撑。
2. **冲突被悄悄抹平**：两份文件要求不一致时，模型倾向给出一个折中结论，读者看不到分歧。
3. **看起来完成，实际没验证**：模型说“已完成”，但结果没有通过任何结构化检查。

政策、法规、制度类资料的读者承担的是合规责任，这三个问题直接决定成果能不能用。

## 3. 产品方案

### 3.1 一次使用的完整路径

1. 登录后选择一个预置工作区（`ai-governance` 或 `education-policy`）。
2. 输入目标，例如：“中小学使用生成式人工智能辅助教学时，学校和教师需要注意哪些要求？”
3. Leader 生成结构化计划，应用侧校验后提交给原生任务板；两名成员分别负责取证与成稿。
4. 任务图实时推进；点击任务节点只看该任务检索到的证据，点击结论只看它引用的原文。
5. 运行结束后生成报告：结论、验收结果、限制、证据、冲突候选、分任务明细，可下载 Markdown。

### 3.2 结论级引用

每条结论必须标注 `[fact]` / `[inference]` / `[assumption]`。标为 `fact` 的结论必须引用**该任务实际检索到并保留给模型**的证据；被上下文预算裁掉的证据不算支撑。成员提交结果时由应用侧校验，不通过的事实会被改标为 `[unverified]` 并排除出交付证据。

### 3.3 冲突候选，而不是冲突裁决

当两条 `fact` 结论来自不同来源、句式相同而数值不同（例如“十个工作日”与“三十个工作日”），报告把它们并列展示：双方原文、来源 URI、定位符（章节/字符区间）、证据编号。系统**不判断谁对谁错**，也不取平均。没有候选时明确写“未发现候选冲突”，并注明检测规则，避免被读成“资料之间没有矛盾”。

### 3.4 可审计与可恢复

- 运行在独立子进程中进行，状态以原子快照持续落盘；浏览器通过 SSE 读取快照，断线重连不触发重新执行。
- 每个任务的结果、证据与产物绑定 execution id；过期执行的结果不能覆盖新执行。
- 会话使用签名 HttpOnly Cookie；不同登录会话看不到彼此的运行。

## 4. 技术架构

- **底座**：OpenJiuwen / JiuwenSwarm，锁定到固定提交（agent-core `6df9699`、jiuwenswarm `3fea8d1`），不使用浮动分支。
- **团队**：1 名 Leader + 2 名专业成员（Research / Engineering），原生 `scheduled` 调度器按 assignee 拉起成员，任务板由框架拥有，应用不另建第二套调度。
- **门禁**：计划校验（无环、依赖存在、验收声明）、依赖门禁（前置必须有当前执行的有效产物）、完成门禁（结果、执行、验收、评审人独立性）、引用校验、结构化验收。
- **工具面**：公网运行只暴露 `retrieve`、`build_team`、`view_task`、`async_tasks_list`、`async_task_output`、`submit_task_result`；在模型请求层与执行层同时拒绝 shell、文件、spawn 等工具，并记录被拒绝的调用。
- **检索**：SQLite FTS5 trigram 中文索引；每个工作区一个独立数据库（`data/corpora/<corpus>.db`），授权边界就是“打开哪个文件”，检索 SQL 不跨语料。
- **部署**：单容器镜像，FastAPI 同源提供 API 与 SPA；CloudBase Run 单实例、HTTPS 域名、健康检查；首次启动按工作区自动建索引。

## 5. 创新点

1. **结论级引用与“实际收到”的可判定定义**：引用是否有效，按该任务检索工具返回并保留下来的证据集合判定，而不是按“语料里有没有这条”。
2. **冲突保留**：候选冲突并列呈现，系统只做机械化的句式/数值比对，不做语义裁决，避免把“模型觉得矛盾”当成事实。
3. **真实委派**：应用提交已分配的任务图，由原生调度器拉起成员；成员通过受校验的工具回传结构化结果，而不是由 Leader 在一段文本里“假装分工”。
4. **可审计的终端状态**：只有原生 `team.completed` 且退出码为 0 才算成功；超时、空闲、崩溃都进入失败态并写明原因，不会把“看起来跑完了”当成完成。

## 7. 应用价值与推广

- **教育**：学校在引入 AI 教学工具前，需要把《教育法》《未成年人网络保护条例》《未成年人保护法》等文件的要求落到具体动作；工作台把“读文件”变成“可引用的合规清单”。
- **企业合规**：同一引擎更换语料与提示词即可用于数据合规、行业监管、内部制度问答，无需改代码。
- **可复用性**：工作区是“语料 + 提示词 + 访问范围”的配置；新增一个领域只需准备公开文件并注册，不需要新写一套 RAG。

## 8. 已知限制

- 公网演示不开放文件上传与 shell/文件工具，这是安全取舍；通用工具能力属于赛后路线。
- 当前部署未挂持久卷，实例重启后运行历史与索引会重建（预置语料会自动重新导入）。
- 固定三成员名册；依赖型任务的评审流程尚未在真实调度器中验证，回退计划保持两任务并行。
- 现有 AI 法规语料中没有“同句式、不同数值”的真实冲突对，冲突面板在演示中可能显示空状态。
