# 演示视频脚本（约 4 分 30 秒）

> 目标：让评委在 5 分钟内看懂“谁在干活、结论从哪来、凭什么可信”。
> 原则：全程真实运行，不剪辑伪造结果；一次 run 至少 2–4 分钟，可倍速但不要跳段。
> 录制前：确认公网链接可登录、模型额度充足；关闭无关标签页与通知。

## 录制要点

1. **先预热一次 run**，确认模型可用；正式录制时重新开一次，避免拿旧结果冒充。
2. 任务图节点出现后**不要加快进**，让评委看到状态变化；中间等待可 2 倍速并加字幕“真实等待，未剪辑”。
3. 证据抽屉一定要展示**正文 + 来源 + locator**三样，这是与普通 RAG 的分界。
4. 报告里的“冲突候选”若为空，照实说：“这份语料没有检测到同句式不同数值的冲突，系统明确写出未发现，而不是暗示资料一致。”
5. 不要在视频里展示账号密码、API Key、控制台密钥页。
6. 结尾给出可点击的链接；视频简介里再放一次。

## 备用镜头（若某一步失败）

- 真实运行失败时，不要重录掩盖；保留失败态并说明原因，再切到一次已成功的报告。评审更看重“失败可见”，这本身就是产品主张。
- 网络抖动导致 SSE 断开：刷新页面会从快照续读，不会重新执行——这正好可以作为一个 10 秒的补充镜头。
