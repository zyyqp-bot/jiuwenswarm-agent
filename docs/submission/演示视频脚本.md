# 答辩视频脚本（详细版 · 5 分 40 秒，上限 6 分钟）

> 文件名：`【教育-重庆邮电大学-赵乙亦-证据工作台】.mp4`
> 格式：MP4，1080p，≤300MB；**画面和旁白里不能出现学校、姓名、指导教师**。
> 原则：真实运行，不伪造结果；失败镜头保留并解释，这本身就是产品主张。

## 一、录制前 15 分钟准备

### 1. 设备和画面
- 浏览器用 Chrome 或 Edge，窗口最大化，页面缩放 **100%**，隐藏书签栏。
- 关闭微信、QQ、系统通知；退出会弹通知的软件。
- 录屏软件设为 **1920×1080、30fps**，麦克风单独试录 10 秒回放。
- 准备两个标签页：
  - 标签 A：公网链接（用于现场跑）
  - 标签 B：AI 治理工作区的历史报告（4:30 切过去展示，不用现场等）

### 2. 登录与预热
1. 打开 `https://workbench-335317-9-1515867239.sh.run.tcloudbase.com`
2. 首次会看到腾讯云“页面访问提示”，点 **确定访问**。
3. 进入落地页后，点「点击进入」→ 登录。
4. 账号 `judge1`，密码从 `deploy/.env.production.local` 的 `WORKBENCH_USERS` 复制。
5. **先完整跑一次**，确认模型额度、网络和报告都正常；正式录制时重新登录、重新跑，不拿旧结果冒充。

### 3. 必背的两句话
- “每条结论都能回到原文。”
- “冲突并列展示，系统不裁决。”

### 2:10–2:50　现场演示：Agent 开始工作

**操作**：
1. 点「开始研读 ↑」。
2. 出现你的问题气泡，下面出现「Agent 团队」卡片。
3. 等 2–3 秒，让四步进度（规划 / 分派 / 检索 / 汇总）依次点亮。
4. 指针移到屏幕最下方，让收起的输入栏滑出来，再移开，展示「继续提问」胶囊。
5. 等「证据」数字从 0 开始上涨。

**旁白**：
> “提交后，输入栏会自动收起，把屏幕让给结果；鼠标靠近底部可以继续提问。现在 Leader 已经规划完，任务板出现两个任务，两名成员开始检索。页面通过 SSE 实时更新；如果网络断开，刷新会从快照续读，不会重新执行。”

**字幕**：SSE 实时推进 · 断线不重跑。

**注意**：等待时间不要剪掉。后期可 2 倍速，但加字幕“真实等待，未剪辑”。

### 2:50–3:30　现场演示：点任务、点结论看原文

**操作**：
1. 点「任务图」里的 **T1-research-policy-basis** 节点。
2. 右侧「证据」只显示这个任务检索到的片段。
3. 指针指向一条证据，让镜头看清三样东西：**文件名、章节定位、原文正文**。
4. 在上方点一条带 `[fact]` 的结论。

**旁白**：
> “点任务，只看这个任务检索到的证据；点结论，只出现它引用的原文。来源、修订、章节定位都在。被预算裁掉的证据不算支撑——成员没看到的证据，不能拿来证明它说过的话。”

**字幕**：点任务 → 该任务证据；点结论 → 它引用的原文。

## 三、术语对照（自己看懂用，不用念）

| 脚本里的词 | 人话 |
|---|---|
| Agent 团队卡片 | 运行状态区，显示谁在干活、干到哪一步 |
| 任务图 | 这次运行的待办列表，两个任务对应两名成员 |

| 快照 | 运行状态的存档，刷新页面时从这里恢复 |

## 四、录制与后期要点

1. **不要剪掉等待**：任务执行需要时间，观众需要看到它是真的在跑。可 2 倍速并加字幕。
2. **鼠标慢一点**：每次点击前停 0.5 秒，让观众看清点的是哪里。
3. **只截内容区**：不要拍到浏览器账号栏、个人中心页头、控制台密钥页。
4. **错误镜头保留**：如果某一步失败，保留并说明原因；不要重录掩盖。
5. **导出**：H.264、1080p、4–6 Mbps，文件控制在 300MB 内，按官方文件名命名。

## 五、如果现场出问题

| 问题 | 处理 |
|---|---|
| 模型超时 / 运行失败 | 保留失败画面，说明“失败可见”是设计的一部分，再切到已成功的报告 |
| 网络断了 | 刷新页面，说明会从快照续读，不会重新执行 |
| 冲突面板为空 | 按上面的原话解释规则，不要编造冲突 |
| 页面一直停在“启动中” | 等 30 秒；仍无进展就切到已完成的报告，并如实说明 |
| 官方链接打不开 | 先点“确定访问”；仍不行就检查环境是否到期（11-26） |
